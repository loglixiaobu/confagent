# ConfAgent：三分钟了解项目

更新：2026-10-21。**目标：让智能体知道哪一步可能出错，优先复查，再把有效纠错经验用于后续任务。** 当前完成的是步骤评分与概率校准的最小原型。

## 1. 我们具体在做什么

智能体是会调用查询、计算、预约等工具的语言模型。本项目用 Qwen3-8B 在 API-Bank 多步工具任务上实验，工具返回来自数据集模拟环境。

例如，创建会议时缺少地点，模型自行编造地点就是错误；每次查询都合理，但没有完成预约，整个任务仍然失败。**调用正确、任务完成要分别评价。**

目前流程：**候选调用 → 在相同调用前状态额外采样 3 次 → 看多少次与候选等价 → 映射为正确概率 → 输出复查建议。** 比如 2/3 次一致，原始分数就是 2/3；历史标签训练出的简单映射，再把它转换成概率。评分不读取本次调用结果或参考答案。

“校准”就是：声称有八成把握的一组步骤，应当约八成正确。**现在只输出建议，还没有自动验证、纠错或更新经验。**

## 2. 已经完成了什么

| 工作 | 结果与含义 |
|---|---|
| 标签清洗 | 原 50 个任务、198 次调用修订为 **158 正、40 负**，保留原标签和依据。改标签不等于模型变强。 |
| 三种信号比较 | 同一批 198 步上，logprob（生成 token 的概率）、自陈（模型自报分数）、一致性 AUROC 分别为 **0.6351 / 0.7172 / 0.8812**；一致性最值得继续验证。 |
| 内部概率校准 | 将任务分成五组，每次用四组拟合、另一组评估；Brier **0.1235 → 0.0917**。仍是旧数据上的开发结果。 |
| 新任务验证 | 固定模块参数后跑 **30 个任务、50 次调用，49 正 / 1 负，任务交付合格 22/30**。校准 Brier **0.0599**，差于固定预测旧数据正确率的基线 **0.0527**，也未胜本轮 logprob。 |

新任务只有一个调用错误，**还不能证明评分与校准能稳定推广**；新旧任务不同，也不能把成功率差异当作能力提升。标签由屏蔽分数的模型代理复核，尚无独立人工双标。

## 3. 指标怎么理解

| 指标 | 看什么 |
|---|---|
| AUROC ↑ | 能否把正确步骤排在错误步骤前面；0.5 近似随机，1 理想。**不等于准确率。** |
| Brier ↓ | 预测概率与正确／错误标签的平均平方误差，综合衡量概率好不好。 |
| ECE ↓ | 把相近概率分组，看预计正确率与实际正确率差多少；受分箱和样本量影响。 |
| NLL ↓ | 对高置信却判断错误的情况惩罚很重。 |
| 错误捕获率 ↑ | 选中的待检查步骤包含了多少真实错误；**发现位置不代表已修复。** |
| 调用正确率／任务成功率 ↑ | 前者看单次调用，后者要求完整满足需求且交付正确。 |
| 请求数、token 数 | 模型计算开销，必须包含评分、检查和重试。token 是模型处理文本的单位。 |

图中误差条是 95% 不确定区间；“相对提升”的区间跨过 0，表示当前证据不足以确定提升。

## 5. 核心代码读哪些

| 文件 | 用途 |
|---|---|
| [`relabel_binary_steps.py`](../code/relabel_binary_steps.py) | 清洗调用、结束和任务标签，保留原值与判定依据。 |
| [`collect_new_signals.py`](../code/collect_new_signals.py) | 固定旧调用，补采自陈与一致性，不执行新工具。 |
| [`evaluate_new_signals.py`](../code/evaluate_new_signals.py) | 比较三种信号的 AUROC、捕错率与不确定区间。 |
| [`calibrate_consistency.py`](../code/calibrate_consistency.py) | 分组评估概率映射，再用旧数据拟合并冻结校准器。 |
| [`confidence_runtime.py`](../code/confidence_runtime.py) | 实际评分入口，输出 `p_correct`（正确概率）和 `needs_verification`（是否建议复查）。 |
| [`evaluate_minimal_validation.py`](../code/evaluate_minimal_validation.py) | 复算新任务上的评分、任务结果、检查预算和成本。 |

画图用 [`build_presentation.py`](build_presentation.py)；接入与复算方法见[接口说明](../code/README_step_confidence.md)，完整依据见[中期报告](中期研究报告.md)。

## 6. 下一步：设计与验证

以下是计划，按顺序推进，尚未作为实验结论。

| 阶段 | 最小设计 | 怎么验证 |
|---|---|---|
| ① 补足评分证据 | 固定现有采样与校准规则，在未参与现有实验的同类新任务上收集自由执行轨迹；分别标注调用和任务结束。 | 预先固定任务及预算，按任务隔离开发／测试，测试集不调参；比较 AUROC、Brier、ECE 与固定先验、logprob。自然错误不足时只报探索结果，不用重试或合成错误凑独立样本。 |
| ② 接入局部纠错 | 先只做调用前检查：低一致性时核对参数来源和单位；每任务最多检查一次、修正一次，缺输入则追问。 | 同一批任务、相同模型与总 token 上限，比较**不检查／随机检查／一致性触发检查**；后两组共用检查器与检查次数上限。看任务成功率、修好／误改数量和总开销，包含全部评分成本；追问未得到回复时不计为已完成。 |
| ③ 复用有效经验 | 只保存经核验的通用规则，如“调用前换算单位”；先用可检索记忆，不急于训练模型。 | 固定纠错流程，在未参与经验构建的任务上比较有／无记忆；测试答案不写入记忆。任务成功率与开销改善，才支持经验复用有效。 |

下一次优先交付：**新任务评分是否可靠，以及相同预算下复查能否实际提高任务完成率。**
