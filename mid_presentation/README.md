## 可以汇报的主线

1. 旧标签存在大量环境与参考误判；同一 198 次调用修订为 158 正、40 负，不代表模型能力提升。
2. 同标签探索性比较中，一致性 AUROC 0.8812，配对优势区间未跨 0；自陈的优势尚不确定。
3. 按任务 OOF 校准改善内部 Brier、ECE，但不能消除先在同批数据筛选信号的偏差。
4. 冻结后新跑 30 个任务、50 次调用，49 正、1 负，任务交付合格 22/30。错误太少且新域 Brier 未胜常数先验或 logprob，泛化仍待验证。
5. 参考前缀缺负例、长思考补采早停、合成压力测试未完成独立检验，均作为研究教训单列。

工具调用分数不覆盖所有结束事件；自主验证纠错、经验更新及递归能力提升尚未实证。

## 数据与复现

- `data/experiment_ledger.json` / `.csv`：21 条阶段、原型、中间文件与发布记录，**不是 21 组独立实验**。其中 `sources` 是历史归档的相对位置；不代表所有原始材料均已上传。公开资料以本目录链接和公开来源清单为准。
- `data/core_metrics.csv`：旧信号、内部校准与新任务的主要指标。
- `data/strict_verification_budget.csv`：统一严格 39/198 步预算，分别列同分随机期望与固定种子实际捕错。
- `data/presentation_data.json`：生成图表所需的数值快照与冻结逐步分数。
- `data/source_manifest.json`：本次公开来源文件及数值快照的实际大小和 SHA-256。
- `data/archive_source_manifest.json`：整理报告时的归档来源校验值；部分原件未公开，部分公开文件已精简，不能把这些值当成公开文件的校验值。
- `data/figure_manifest.json`：图名、主题和要点。
- `data/figure_texts.json`：逐图标注文本，用于核对图片全部使用英文。
- `validation.json`：数值、链接、图像、PDF 和文件内容检查记录。

图 04 沿用原校准脚本的 NumPy 随机算法及冻结输入顺序：39 步实际捕错 65.0%，同分随机期望 67.65%；历史 68.69% 使用 39.6 步的期望预算，不能混用。

使用随目录发布的数值快照重新渲染，无需模型服务或 GPU，也不依赖未公开的原始请求日志：

```bash
python mid_presentation/build_presentation.py
```

依赖 Python、NumPy、Matplotlib；汇报 PDF 的中文页面优先使用系统 Noto Sans CJK。脚本不安装软件、不联网、不改动原实验结果。

完整报告 PDF 使用 Python 环境中的 ReportLab、Pillow 直接读取 Markdown 和图表导出；PNG/SVG、横版汇报 PDF 与 HTML 由构建脚本生成。重新导出完整报告 PDF：

```bash
python mid_presentation/export_report_pdf.py
```

公开版仅提供离线重绘；采集日志、服务启动信息和运行环境记录不在发布范围内。指标复算入口见 [最小置信度模块说明](../code/README_step_confidence.md)。
